## TypeScript and contracts

Enable strict mode, unchecked-index protection, and exact optional-property handling. Use `unknown` and validation at untrusted boundaries instead of `any`. Use named domain types/enums from contracts rather than repeated literals. Keep transport, provider clients, workflow transitions, persistence, and scientific eligibility separate.

Zod definitions are the TypeScript contract source and emit versioned JSON Schema. Python Pydantic models must pass shared valid/invalid boundary fixtures and schema-compatibility tests; do not independently evolve equivalent-looking fields. Schema shape validation does not establish physical meaning or truth.

Use explicit return/error types, exhaustive state handling, and operation IDs. Public JSON uses camelCase; Python internals use snake_case with explicit serialization aliases. Store UTC timestamps, integer byte counts, and integer micro-USD. Do not put credentials or filenames into executable syntax.

Async external I/O uses bounded timeouts/cancellation and accounted retries. Await dependent operations in order; batch independent reads where safe. Do not bury automatic paid retries inside SDK defaults or catch and ignore ambiguous outcomes. Keep streamed files out of whole-body buffers when unnecessary for validation.

MetaRequest is the strict stateless Responses wire contract. Counting and inference serialize the same validated body with the same digest; never translate a Chat request to a different protocol and reuse its count. Context promptVersion=context.2 binds this shape. Keep provider Responses usage adaptation in meta-client.ts and retain existing internal accounting field names only behind that adapter. Preserve valid usage on output failures, include reasoning in total output and discard reasoning text. ContextTokenMeasurement is a context-fit observation, not ModelTokenEvidence or a monetary estimate. ContextTokenCounts implements its mandatory disclosure/one-shot port; no production no-op gate, automatic verification attestation or count-to-billing shortcut is allowed. Bounded replay must reauthorize, and a losing claimant must never mutate another invocation's journal.

Use DocumentTransaction.getMany for independent document reads with already known identities; never correlate batchGet response order with request order. FirestoreClient validates identities and caches reads only within the current transaction, including overlapping get/getMany calls. Preserve read-before-write, bounded distinct reads and independent returned snapshots. Do not introduce production emulator endpoint or authentication bypasses. Keep metadata-only orchestration phase methods separate from the one-shot provider callback and recovery; no raw source or live SDK session is returned as a durable checkpoint.

AccountingTransaction.getCounters returns all requested charge counters in caller order; reject duplicate/incomplete accounting inputs before writes. Private readBatch launches only a bounded transactionally authorized group, accounts its attempt ceiling and verifies/disposes every stream before returning all-or-nothing bytes. Inspection selection comes from server-held manifests, never AI executable logic; it supplies sourceBytes as the cumulative bound and rechecks identities/hashes. Preserve both pre-dispatch and post-transfer authorization while batching independent reads.

apps/api/worker/index.ts is the native entrypoint exporting HTTP and SiphonInspectionWorkflow. Root TypeScript excludes only this native wrapper; the separate native project includes it and its SDK dependencies. Shared FirebaseServiceConfiguration uses safeExtend so API/Workflow extensions preserve service-account/project refinements. Inspection runtime configuration remains disabled by default. The workflow driver validates payload/checkpoints/outcome, uses fixed retry-disabled stages and stores metadata only. Raw internal exceptions stay outside execute receipts and native Workflow errors. Cleanup uses a separate deadline and recorded handle; no session reconnection or lifetime extension. Copy evaluator request bytes into owned ArrayBuffers rather than casting away native SharedArrayBuffer-compatible encoder types.

## Scientific Python

Report formatting: EvidenceReport owns scientific display data and runtime consistency refinements. report-layout.ts is a deterministic projection to PdfRenderDocument; never round decisive metric/support/interval values, invent missing values or let narrative change a verdict. PdfRenderDocument is a separate presentation-only protocol, not a second scientific model. Python receives only bounded layout bytes and validates them through pdf_models.py, including strict aliases/types/extra-field rejection, exact shared timestamp syntax, plot bounds and duplicate JSON-key rejection. Zod/Pydantic acceptance and accepted serialization are exercised by npm run test:report-pdf. This does not establish authoritative report assembly or provider execution.

Escape every string before ReportLab Paragraph XML parsing. Do not add raw HTML, arbitrary images, local resource paths, dynamic fonts or template evaluation. Keep fixed font asset hashes/license with the package, explicit unsupported-glyph/shaping errors, output/page guards and source-independent drawing code. Scale extreme finite plot coordinates before subtracting ranges. Do not use plot display rounding/downsampling as a numerical evaluator. ReportLab 5.1.0, Pillow 13.0.0 and charset-normalizer 3.5.2 are pinned runtime additions; pypdf 6.21.4 is a development verification dependency. The PDF function does not launch an E2B environment and must not become a local fallback for a hosted PDF job.

Observation export validation receives byte payloads and server-owned mapping/identity metadata only. It must rehash all declared files and enforce cumulative resource limits before NPY decoding. require_float64 prevents coercion of integer/float32 observation output; allow_scalar is enabled only for declared scalar gravity parameters. Keep both options off for ordinary numeric-upload parsing unless an explicit supported format policy authorizes them. Readonly decoded arrays and conversion metadata do not establish physical semantics or genuine execution. Trusted evaluation must never import an uploaded module or execute a source namespace.


Static inspection job parity runs with npm run test:inspection-job-parity and SIPHON_PYTHON selecting Python 3.11. The Python -m siphon_science.inspection_job entrypoint consumes a bounded JSON request on stdin and emits bounded JSON only. Local verification must use authored fixtures; uploaded source parsing belongs in fresh E2B inspection environments. No uploaded source may become a shell command, import target, Python eval or local filesystem path. Its request/result boundaries now use strict Pydantic models. Numeric validation requests/results and mapping structure also have typed models. npm run test:python-model-parity checks 93 shared valid/invalid cases and accepted serialization round trips against the real Zod/Pydantic validators. Other contracts still need equivalent coverage.


`npm run test:evidence-parity` runs nine authored numerical decisions in Python 3.11 and validates their serialized values/statuses against the TypeScript evidence contract. It checks floating boundary semantics, not a complete evidence publisher. Use SIPHON_PYTHON for the intended interpreter. Do not replace these boundary checks with JSON Schema alone: verdict/interval consistency uses runtime refinements.

`npm run test:fidelity-parity` validates three fixed authored Python baseline comparisons against the TypeScript contract; set SIPHON_PYTHON to Python 3.11. It never loads uploaded scripts. Exact baseline fidelity uses numeric array equality with matching shapes, not tolerance-based allclose; coordinate repair/interpolation belongs nowhere in a fidelity comparison. Matching numerical output remains distinct from provenance and semantic adapter verification.

Numeric decoding and structural observation validation are now included in the same Python unittest suite. Use Python 3.11 with the tested NumPy 2.0.2 dependency in `packages/science/requirements.txt`. That file pins only the current parsing dependency, not all planned scientific/image dependencies. Observation validators receive canonical axis shapes and server-owned bounds explicitly; they do not infer units, frames or timestep controls from data.

The root `npm run test:inspection-parity` command runs five fixed authored fixtures using Python 3.11 and validates returned inspection results against Zod, including the exact source digest. Set SIPHON_PYTHON to the intended interpreter if needed. This command is not an uploaded-source runner. It supplements scientific tests and the shared invalid-fixture parity suite.

Scientific verification is configured in packages/science/pyproject.toml. Install the pinned requirements-dev.txt into an isolated Python 3.11 environment; runtime-only images use requirements.txt. From the repository root use npm run test:science, lint:science, typecheck:science or verify:science. These fixed developer commands use SIPHON_PYTHON, otherwise the ignored .tools/science-venv interpreter when present, otherwise python; they fail before testing if the interpreter is not Python 3.11. verify:science runs dependency consistency, Ruff lint/format, strict mypy for models.py and pytest. pytest collects the original unittest cases plus new shared-boundary cases. No command accepts uploaded source/file paths. Additional scientific runtime dependencies, other typed contracts, hosted images and full release gates remain unfinished.

Pure numerical routines accept validated typed data and explicit accuracy policies; they do not call AI, networks, storage credentials, or user modules. Use NumPy/SciPy rather than reimplementing a trusted algorithm without reason. Keep algorithm/reference implementations independent enough to catch shared-path bugs.

Formula-roundoff enclosures use the standard-library Decimal engine with exact from_float conversion and private directed contexts. Never use Decimal(str(float_value)) when the claimed input is the exact represented binary64 value, or global Decimal arithmetic when endpoint rounding must be controlled. Negation/absolute-value copies must not accidentally apply ambient precision. Decimal sqrt is bracketed using adjacent context values; endpoint/radius serialization is checked for outward binary64 conversion. Keep arithmetic bounds distinct from spatial/time quadrature, state uncertainty and user accuracy criteria. Exceeding the fixed versioned arithmetic-work guard preserves a null bound rather than silently lowering precision or dropping samples.

Specify shapes, dtypes, units, node/cell interpretation, quadrature weights, frames, normalization scales, and allowable assumptions. Use float64 for the initial supported numerical pipeline and record conversions; reject unsupported precision rather than silently misrepresenting it. Do not infer physical units from variable names or magnitudes.

Avoid universal `allclose` thresholds, division by near-zero invariants, unlabelled epsilon constants, and implementation-mirroring tests. Every scientific threshold needs a named policy, dimensional interpretation, rationale, and validation. Diagnostic display rounding never affects decisions. Machine arithmetic bounds, discretization estimates, and user accuracy requirements are different quantities.

A reference solver comparison requires matching force/boundary models and independently checked reference accuracy. Passing conservation does not prove trajectory accuracy. Do not call refinement convergence physical validation. Budget insufficiency is not evidence of a physical defect.

## Adapters and audit-only behavior

The source_job Python library executes code and therefore belongs exclusively in a fresh untrusted source VM. The development suite and npm run test:source-job-parity may call it only with fixed authored fixtures. Do not build a local fallback for real uploads. Source invocation is versioned as runpy_main_root_v1; changes to cwd/argv/import behavior require explicit profile review. Exported manifests and NPY bytes remain untrusted until separate collection/hash/format checks. Retained-output caps include serialization headers; scratch disk/process/resource enforcement must come from the provider, not a Python check.


The initial AdapterProposal/ObservationMapping contracts allow only named globals and literal key/index selectors, explicit axis permutations, expected canonical shapes and declared units. The Python extraction helper accepts exact built-in containers and native float64 arrays only, with cumulative server-provided byte/element caps and read-only copies. It belongs in an untrusted source sandbox. It is not a source executor or trusted-evaluator API. No dtype conversion, scaling, expression evaluation or property traversal is allowed through this profile. npm run test:adapter-parity exercises one authored extraction and three invalid selector cases across TypeScript/Python; use SIPHON_PYTHON for Python 3.11. This supplements, not replaces, future Pydantic and broader contract parity.


Context extraction uses ContextProposal for model suggestions and bounded source citations. Source-location validation cannot certify semantics. Context question definitions and option mappings are deterministic reviewed rules; fixed options produce user declarations only. Preserve custom text beside selected options and keep unresolved states explicit. No conversion from a model candidate or user declaration directly into eligibility assertions is authorized by these helpers.


Keep uploaded source immutable. AI proposes declarative mappings to reviewed callable/script handlers. Record extraction and permissible experiment override locations. Do not generate an unrestricted wrapper that silently rewrites equations, defaults, or solver semantics. Baseline discrepancy blocks dependent checks.

Observability instrumentation must be documented and verified. Headless plot handling cannot justify altering numerical behavior. No repair patches, simulation-code generation, or apply-fix UI. Recommendations remain explanatory and evidence-based.

## Errors, logging, and configuration

Use Architecture's error envelope and state enums. Separate invalid upload, unsupported scope, missing assumptions, provider faults, numerical flags, cancellation, and budget stops. Errors expose safe next actions, not secret-bearing traces.

Structured logs carry request/operation/audit/revision identifiers, stage, safe error code, and duration. Do not log complete source, raw private answers, tokens, credentials, or unbounded stdout/model output. Keep user-visible progress bounded and distinct from internal telemetry.

All Product LIM values come from one validated versioned implementation policy; do not duplicate numeric defaults across services. Scientific check constants and predicates belong to a reviewed versioned registry, not editable user config or model output. Model IDs, provider endpoints, project IDs, template IDs, storage bindings, origins, and secrets use environment/bindings with startup validation.
