# Siphon security specification

## Advisory publication boundary — 2026-11-11

Investigation consumes only the owned published conservation snapshot, not uploaded modules or numeric array payloads. The Groq dispatch revalidates the live revision, evidence provenance/expiry, task/request/configuration identity and reserved quotas. Sanitized usage must be settled before a draft can be displayed for review. Evidence-ID and identity checks, plain bounded text and rejection of fenced code blocks do not prove scientific truth or detect every executable instruction. The owner must review the advisory text before accepting it; omit is available without changing the numerical evidence. Acceptance is never execution approval, a scientific verdict or an automatic repair action.

The review route inherits invitation/authentication/rate/origin guards, requires a current owned investigating revision and exact draft digest, and journals an immutable decision with an idempotency receipt. Publication revalidates settled accounting and the same evidence snapshot. Pending review blocks report/PDF assembly, while accepted text stays explicitly hypothetical/advisory. No model call, approval record or hosted audit is established by local fixtures.

Before any Groq context, adapter or numeric-investigation request, the owner must explicitly accept the current disclosure shown in the workspace. It names the configured provider, model, endpoint, notice version and data scopes. The server binds acceptance to the current revision input and recomputes the configuration digest; the dispatch transaction rechecks both immediately before dispatch authorization. Revocation prevents later dispatches but cannot recall a request already authorized or transmitted. The source scanner is an additional server-side filter, not a substitute for consent.

## Terminal replay authorization — 2026-11-11

A scientific finish receipt permits replay of the original finishing operation only after rechecking an active invitation, live owned audit, unchanged current revision/input, exact successor generation, matching report ID, partial terminal state and absence of attached capacity/operations. A different operation, deletion, ownership change or superseding revision denies replay. Server-held completion metadata never grants new execution or artifact access, and terminal status without the receipt is insufficient.

## E2B endpoint consistency (2026-11-11)

Only trusted server/operator configuration may select the clean HTTPS control-plane origin. User/model/upload content cannot select it. Reject embedded credentials, paths, queries and fragments before I/O; do not echo malformed endpoints or provider exceptions. Shared runtime/audit template verification bounds metadata and disables redirects/retries. Cleanup binds the SDK client to the same origin, retains kill authorization, and records termination only from a known boolean outcome. Configuration changes cannot serve as evidence that an old provider handle terminated.

## Current AI provider boundary (2026-11-08)

Groq free-tier inference supersedes the Meta selection, Standard-mode rule and USD 150 assumption below. Old Meta code is legacy compatibility/history, never a production fallback. Invalid or absent explicit Groq settings block dispatch; a key does not authorize a paid upgrade, provider change or uncertain-operation retry.

Keep `GROQ_API_KEY` only in ignored `apps/api/.dev.vars` locally or a hosted Worker secret. Never expose it through `VITE_*`, logs, sandboxes, reports or persisted jobs/configuration digests. The configured HTTPS endpoint must match the official Groq origin/path allowlist; arbitrary, credential-bearing and redirect URLs are rejected. Configuration errors must not echo secret values. Verify account free limits and data controls before private-code use.

Disclosure reviews bind source hashes to the configured model/endpoint and scan recognized credential patterns, including Groq tokens; they do not establish universal confidentiality. Recheck ownership, current revision, source expiry and immutable job/request configuration before dispatch. Independent full-request byte screening is not rendered-token measurement; reserve configured full input/output tokens, reconcile actual usage, halt overruns and preserve uncertain reservations. Strict JSON and original Zod validation do not establish truth or override scientific decisions. Service/database configurability does not make protocol allowlists or scientific/security invariants arbitrary settings. No live security certification is claimed.

## Scope and ownership

[Product requirements](PRODUCT_REQUIREMENTS.md) defines supported uploads, invited access, and canonical LIM defaults. [Architecture](ARCHITECTURE.md) defines trust separation/interfaces; [Database](DATABASE.md) defines records/retention; [Testing](TESTING.md) defines verification. This document owns security requirements. A documented control is not an implemented control.

Assets: private source, answers, scientific evidence, reports, provider credentials, credits, project data, host infrastructure, and audit integrity. Threats include malicious invited users, compromised credentials, hostile dependencies/source, prompt injection, generated adapter errors, cross-user access, resource exhaustion, forged observations, and ambiguous external outcomes. Siphon cannot prove that hostile source honestly reported its intended physics.

## Identity and authorization

Use Firebase Google sign-in. Verify bearer ID-token signature, allowed algorithm/key, issuer, audience, subject, expiry/issued-at, and required identity claims using current Firebase guidance and bounded cached keys. Fail closed on invalid/unverifiable tokens; never accept decoded-but-unverified JWT claims.

An active invitation uses verified UID, not a user-supplied email/body field. Verify invitation and ownership on protected API requests and stage admission; recheck before subsequent paid dispatch. Server derives owner UID and checks audit deletion/current revision. Use 404 for missing/other-owner objects, 403 for uninvited users. Firestore rules separately protect direct browser reads; deny browser writes and privileged collections. Backend service accounts bypass those rules, so API checks cannot be omitted.

Admin invitation/policy changes are out of band; no public admin endpoint in v1. Allow only configured frontend origins; use bearer headers rather than ambient authentication cookies for API authorization. Do not embed credentials in URLs. Restrict authorized Firebase domains to actual local/staging/production hosts. Sign-out disconnects subscriptions and clears client caches.

The Worker entry point now validates required project/service-account/origin/binding configuration and composes the existing verification/authorization repositories without permissive production defaults. SIPHON_API_ENABLED and all public deployment routes are off in the committed Wrangler configuration. The edge binding is required before JWT/Firestore work; its per-location approximate limit does not replace exact user limits or financial reservations. Malformed configuration returns a sanitized no-store 503. Service-account keys stay in ignored local variables or secret bindings; the committed example contains empty credential fields. No credentials or cloud resources were configured by the local build.

infra/firebase/firestore.rules implements a Google/invitation/owner/tombstone-based browser allowlist, bounded queries and expiring final display records, with all browser writes, artifacts, candidates, execution/accounting/configuration records and unknown paths denied. All ten local emulator scenarios passed on 2026-10-29; the rules have not been deployed. The dedicated rules-check script is restricted to a loopback emulator and demo project ID. IAM still governs server credentials, which bypass browser rules; local rules tests do not establish deployed protection. Local OpenSSL-generated test keys are ephemeral authored fixtures, unrelated to application credentials.

Firebase CLI/rules SDK development dependencies are pinned with narrow transitive overrides for the reviewed gRPC certificate, OpenTelemetry baggage and UUID buffer-check advisories. Installation and production-only audit reported no known vulnerabilities after these changes. These overrides do not enter the Worker API runtime dependency graph. CLI startup/module smoke checks and the ten emulator scenarios pass; future dependency updates require renewed verification. Do not use a forced audit fix that silently downgrades the SDK or changes unrelated dependencies.

Python inspection and numeric-validation jobs now reject malformed structure through strict Pydantic wire models, forbid extra fields/internal snake_case aliases, and validate output identities/counts as well as input structure. JSON integer-valued numbers are normalized consistently with Zod; booleans and numeric strings remain rejected. CLI error envelopes remain fixed/redacted; do not log Pydantic errors() payloads, which may contain original input. The 93 shared boundary cases and authored scientific fixtures are local evidence, not proof of hostile-input isolation, safe uploaded execution or physical correctness. Runtime dependencies and development tooling are pinned separately; neither installing packages nor local tests establishes an approved E2B image.

## Uploaded content and readiness

Database batching does not replace authorization: invitation, owner/tombstone, current revision/fence, artifact metadata and accounting are still checked by their repositories. Batch results must match every requested full document identity exactly, and overlapping transaction reads share only that transaction's snapshot. Partial/mismatched results fail closed. The REST emulator transport is test-only, fixed to demo-siphon-rules and validated loopback, and never reads real credentials or offers a production override. Its emulator owner marker bypasses rules only for REST administration tests; the separate browser-rules scenarios continue to verify owner and denial behavior.

Durable inspection phase checkpoints contain bounded job metadata only. A reservation resume validates the saved claim before cleanup/refunds; preparation cleanup closes preparing atomically against dispatch before releasing allowances. execute remains one-shot, returns only a strict metadata receipt/fixed failure code, and never checkpoints source, AST, raw exceptions or a live SDK session. cleanup uses durable operation/handle linkage and may run after cancellation; matching persisted proof avoids another provider kill. It does not grant evidence continuation. finish reauthorizes before publishing/releasing current evidence; unknown creation/termination retains uncertainty. The native Workflow disables automatic retries and masks step/entrypoint errors with fixed NonRetryableError messages.

ArtifactDownloadService.readBatch is internal, with no HTTP route. It validates unique bounded IDs/bytes and transactionally authorizes the complete group before launching reads, respecting current/original artifact policies and the verified Class B allowance. Every stream is hash/length checked and disposed; all sibling promises settle before failure. No partial payload escapes. The final transaction rechecks invitation/current fence, unchanged policy, artifact readiness/expiry/identity and the exact private journal. Cancellation/deletion/revocation/data changes discard bytes while preserving conservative attempt charges. Group admission replaces repeated per-file transactions without bypassing current authorization, accounting or post-transfer verification.

SIPHON_INSPECTION_WORKFLOW_ENABLED is independently false by default. The native runtime validates a matching Firebase service account/PEM envelope, bounded E2B key and private storage binding before constructing dispatch services. Actual template/credit gates still decide admission. No public trigger exists. The full SDK bundle now starts in local workerd; the disabled native Workflow fails without external calls and without exposing authored private markers. That probe reads no real credentials/.dev.vars and uses only ephemeral local bindings with network blocked and telemetry disabled. It does not verify enabled hosted execution, isolation, invocation/CPU limits or billing. Free-plan feasibility remains a release gate; no paid service was enabled.

The internal RunQueue validates the current owner/invitation, complete upload/answer hash and every source artifact's exact ready/unexpired metadata before freezing a draft. It initializes only missing revision caps and never mints global credits or trusted template evidence. InspectionCoordinator uses the existing admission/accounting/sandbox/inspection ports, exclusive preparation and dispatch-phase claims, current fencing and server-held configuration. Duplicate calls cannot re-enter the provider pipeline. Recovery reconstructs actual per-source parser results and the deterministic gate, and verifies aggregate hashes and termination; a changed gate/result/source is rejected. All stageJobs records are server-only. This path does not establish physical readiness or authorize uploaded-code execution, and no public start endpoint exposes the separately gated native Workflow.

Known unused/terminated work can release only the corresponding safe resources. Ambiguous creation/kill retains accounting/capacity until proof exists. A released lease replay must match owner/audit/revision/input and an empty pending inventory, be absent from both capacity ledgers and differ from the revision's current lease pointer; it performs no writes to a newer lease. Cancellation/supersession still denies live-stage recovery, leaving maintenance responsible for late cleanup. No phase timeout is treated as proof of provider termination.

Enforce Product file/size/dimension policies before expensive work. Accept only specified extensions and validate content, encoding, safe paths, total bytes, and numeric formats. Reject absolute paths, traversal, symlinks, duplicate/case-colliding paths, null bytes, executables, archives, pickle, and NumPy object arrays. No path extracted from user content may escape the assigned workspace.

The local inspection runner now uses a fixed Python isolated-mode module command and a single-use execution claim tied to the sandbox/job/source manifest. It validates source hashes before remote I/O and bounds returned JSON; no uploaded path or source expression enters command syntax. Session handoff now uses the original fresh SDK connection; private source loading verifies hashes and revision access around accounted reads, and immutable publication rechecks the active fence. The image, runtime resource controls and live isolation still require verification. Parse without import in an isolated inspection sandbox. Source text, comments, notebooks if ever supported, logs, and data are untrusted, including instructions addressed to an AI. Static scans can flag unsupported operations but are not a substitute for isolation. Handle credentials detected in source as a private readiness issue; do not echo them or send them to a model unnecessarily.

Context-model preparation requires a server-held sourceContextReviews record with exact source hash and purpose=meta_context. The default is rejection when a review is absent or expired; no review records are created automatically. Prompt construction isolates untrusted source in a JSON user input, with explicit anti-instruction and auditor-only developer guidance. This is input handling, not a guarantee against prompt injection or source-secret disclosure. ContextModelGate rechecks disclosure reviews, exact full-request billing-bound evidence, current authorization, pricing and credits within dispatch accounting. The verified billing-bound producer and live provider checks remain missing; no permissive fallback exists. ContextPipeline uses this gate for the same operation it settles and publishes.

Context counting also discloses source. requireContextSourceDisclosure batches exact review/artifact reads and is shared by context preparation, counting and generation authorization. ContextTokenCounts rechecks scope before transport, after receipt and on replay; revocation, cancellation, expiry or changed counting configuration denies results. Its MetaTokenClient requires a mandatory authorization port, fixed official HTTPS endpoint, redirect rejection, bounded bytes/deadline and no retries. The production port claims one count ID and consumes a separate bounded attempt before transport. It requires current operator-verified no-charge availability; no live attestation is fabricated from documentation or test fixtures. A failed/ambiguous attempt remains consumed. A competing caller cannot overwrite the claiming invocation's status. Count journals store fixed errors and scoped measurements, never full requests/source/API keys. A rendered-context count never becomes ModelTokenEvidence automatically or grants paid dispatch. Counter orchestration, secret-review production and hosted verification remain pending.

Responses requests explicitly disable response storage, background execution, streaming, automatic truncation, history and tools. They do not promise zero provider retention. Response parsing rejects unsupported execution output and preserves validated usage for financial reconciliation even if visible output is unusable. Internal return values exclude reasoning content, provider error text and raw response bodies. Responses usage adaptation validates cache/reasoning subsets and accounts for all output tokens; no discount or missing usage is invented.

## Sandbox requirements

Report/renderer boundary: EvidenceReport validity is not publication authority. A trusted assembler must resolve every evidence/catalog/method/experiment reference, released check version and exact revision/plan binding before storing a report; this producer remains missing. ReportRepository exposes only validated owner reads, never a public report-write or render trigger. It checks canonical JSON/hash and retention, preserves historical scope, and marks later retention expiry separately. Unavailable PDF metadata cannot suppress structured evidence or redirect to an unrelated artifact. ReportDownloads rechecks access and exact report/PDF binding after accounted retrieval, cancels denied streams and uses private PDF attachment headers. It cannot retract bytes already delivered after a subsequent revocation.

The reviewed formatter receives a validated report and emits bounded plain presentation blocks; no uploaded source or source module reaches the Python renderer. Its document digest label alone is not authorization: the future PDF execution claim must bind the actual deterministic payload. The renderer accepts no caller-selected font/path/template/image/URL loader. All text is XML-escaped, fonts are fixed licensed/hash-checked assets, and missing glyphs or unsupported right-to-left shaping fail explicitly. Bounded output/page guards complement, not replace, fresh PDF-role isolation and Product accounting. Local fixture tests include literal image/link markup with an image reader that fails if reached, no active PDF annotations, byte-identical rendering, pagination and bounds. Production PDF execution, image verification and safe publication remain unverified.

Use a fresh E2B environment for each original baseline, adapted baseline, and experiment. Keep inspection-only, user execution, trusted evaluation, and PDF environments separate. Never reuse a user-modified filesystem/image for trusted code or another experiment.

- Keep Meta, E2B, Firebase, Cloudflare, and storage credentials in backend secret bindings only. Do not pass application secrets via environment, files, command arguments, mounts, or presigned URLs into sandboxes.
- Explicitly deny outbound networking for source execution. Do not expose public sandbox services. Verify actual SDK/provider network behavior, including DNS and public access, with an integration test.
- Prepare pinned approved dependencies at image construction. No runtime unrestricted installation or network-enabled repair. Record image/template hash and installed versions.
- Enforce Product cumulative time, attempts, outputs, and dimensions through backend reservations. Set provider lifetime to the reserved remaining duration, explicitly kill on timeout, disable auto-resume/pause persistence, and kill on completion/cancellation.
- Request bounded provider resources and verify actual allocation before dispatch. Test memory/disk/process behavior. A Python-level resource limit that uploaded code can raise is defense in depth, not a proven boundary.
- If the selected E2B tier cannot enforce a required security boundary, block hosted release and document it; do not claim enforcement or substitute unisolated execution.

The backend exchanges bounded files through authenticated provider APIs; it never imports source. Use argument arrays/structured commands where supported, generated paths, and robust quoting where unavoidable; never concatenate user text into shell syntax.

The local E2bClient now requests disabled internet/public traffic, empty sandbox envs, no auto-resume, kill-on-timeout, bounded lifetime and zero SDK retries. SandboxJobs now supplies the mandatory creation/accounting gate against server-held template and credit evidence; those approvals/balances have not been provisioned or verified live. E2B defaults and controls must be set explicitly and tested. [Network behavior](https://docs.e2b.dev/network/internet-access) and [lifecycle](https://docs.e2b.dev/sandbox) are provider references, not proof of Siphon's configuration. Never advertise zero risk.

## Trusted evidence and AI

The data-only diagnostics_job launcher never accepts Python source, expressions, arbitrary file paths or model/user tolerance fields. Its strict request selects one reviewed measurement profile; required array units/shapes and policy bounds are checked before decoding. Both numeric validation and diagnostic launchers use the same bounded generated-filename loader, rejecting extra files, symlinks and non-regular handles. The diagnostic job rechecks hashes and actual NPY data rather than trusting a previous report's metadata. Output always remains inconclusive, and full parameter/profile identity is required when consuming it. Metadata labels are not verification of units, frame, physics or adapter fidelity.

The internal diagnostic session, claim/reservation repository and pipeline now exist. They require matching prior published structural validation, source/validator termination identities, current private context/adapter/source provenance and a distinct evaluation-role VM. Expected owner, active revision/fence, policy and report allowance are checked before binding. NumericExecutions fixes the validation/diagnostic protocol and collection namespace in concrete service constructors; no request may choose a permissive lifecycle or bind the same operation to both job kinds. Result transport reauthorizes transfers/execution/acceptance and discards stdout/stderr. Private diagnosticCandidates never become reports until matching termination is recorded; recovery rechecks current access and moves the candidate atomically without extending retention. This grants measurement authority only, not scientific eligibility or a pass/flag. Public endpoints, actual provider security, scheduler and cleanup remain release gates.

Arithmetic enclosures use fixed internal Decimal precision/rounding/exponent/trap settings and a versioned work ceiling; user/model requests cannot change them. API validation rejects reversed/nonfinite/negative intervals, understated radii and a relabelled physical-uncertainty scope. Trusted provenance remains mandatory: structural validation of interval metadata cannot certify its computation. A resource-limited or unrepresentable bound becomes explicit null with a limitation, never a fabricated zero bound or physics defect. These enclosures do not expand model permissions, authorize a check or establish complete uncertainty.

Validation results awaiting termination live only in the server-side validationCandidates collection, with scoped identities, a content digest and report-class expiry. They are not public evidence and no API exposes them. The internal ValidationPipeline attempts termination independently of caller cancellation and publishes only through the repository's persisted-termination/current-authorization checks. Recovery reads the durable candidate without rerunning source or evaluator code, rejects changed/expired results, and preserves retention deadlines. Cancellation blocks both first publication and replay. A failed candidate write cannot guarantee recovery; unknown cleanup retains the existing handle and reservations. Actual private Firestore rules, automatic maintenance and hosted isolation remain release gates.

The Meta transport requires a dispatch-authorization dependency and uses a fixed official HTTPS endpoint with redirect rejection. It sends only the allowed Standard model and separate instruction/data messages, with no tool execution or web grounding. Response format is not trusted as sufficient validation: Siphon parses JSON and its own output schema, checks finish/refusal/tool-call status and usage consistency, and emits sanitized failures. A valid structured response does not confirm physical facts or defeat prompt injection by itself. The future accounting gateway must retain unknown charges and stop further dispatch on usage overruns. No live model calls have been performed by the transport's tests.

After untrusted environments are terminated, validate artifacts in a new trusted environment: lengths, expected formats/dtypes/shapes, unit declarations, finite values, monotonic time coordinates, dimension caps, and source/run hashes. Load numeric files without pickle. No user modules, executable serialization, custom plugins, arbitrary formulas, or runtime check code enter trusted evaluators.

A reviewed fixed check registry computes metrics/eligibility/verdicts. Model output cannot authorize execution, alter a budget, create executable checks, or establish a pass. Validate AdapterSpec against approved handlers and explicit override locations. Mappings, code hashes, and fidelity results are evidence, not AI promises.

Keep uploaded instructions separate from system prompts and treat them as data. Restrict model context to necessary material, use Standard mode, no Contributor model IDs, and validate returned evidence/source references. Do not silently broaden model permissions to fix a failed audit. User content may be processed by configured providers; private access does not imply zero retention by those providers. Verify applicable terms before making privacy promises.

## Storage, reports, and transport

The current private download implementation reauthorizes immediately before returning a response, trusts only a checksum stored by the R2 upload checksum mechanism (never ETag), and validates stream length. It does not independently rehash the complete download inside the Worker. Missing or mismatching stored SHA-256 blocks retrieval. Generated attachment filenames prevent private path/header injection. Deletion denies newly authorized downloads and retrievals still awaiting metadata; already-delivered bytes cannot be revoked. Provider/network correctness and deployed behavior still require hosted probes.

Private R2 bucket, server authorization for downloads, safe MIME/content-disposition, bounded streaming. Validate digests independently of ETag. No public sharing URLs or raw HTML/SVG rendering from uploads. UI renders escaped text and trusted numeric charts. PDFs use trusted rendering and a bundled verified font; user/model strings cannot become shell, Python, HTML, or report-template code. External images/URLs are not fetched during rendering.

Transport uses provider HTTPS endpoints selected from configuration, not user-provided destinations. No credential logging. Redact tokens/source secrets from errors/progress; keep raw source out of application telemetry. Do not cache private downloads publicly. Protect deletion and expiration in authorization immediately, before physical cleanup. Follow Database retention without adding separate contradictory lifetimes.

## Release verification and incident response

Capacity cleanup after cancellation/deletion is an internal maintenance operation, not a user bypass of authorization. It verifies the stored task digest and owner/revision relationship plus durable cancellation/deletion, and rejects any pending or untracked execution. Invitation revocation does not block this server cleanup step. It can only release capacity and stamp that fact; it cannot restore audit access, publish results or report full erasure. Scheduling and sandbox termination remain unimplemented release gates.


The local admission service checks owner, invitation, current revision, cancellation and generation/input fence inside each capacity/admission transaction. It refuses release after possible dispatch unless every tracked operation has confirmed completion and no untracked dispatch exists; it does not treat a timeout as proof of termination. FirestoreAccountingStore now enforces the slot/admission check during operation dispatch marking, atomically with attempt accounting. The Meta transport still requires an injected production gate that actually invokes this accounting path. Reconciliation remains unfinished. Do not deploy a dispatch path that bypasses it or assume a returned running state proves an execution slot is held.

Required negative tests: cross-user reads/downloads/listeners, inactive invitations, token forgery/expiry, prompt injection, traversal/symlinks, non-finite/object-array payloads, network attempts, runaway source, output floods, cancellation races, stale revisions, replayed dispatch, quota races, and failed cleanup. Run exploit fixtures only in disposable environments, never on developer hosts.

Before invited release, record observed isolation, resource enforcement, credentials separation, free-tier CPU feasibility, and deletion/cleanup evidence. No credit-consuming test or paid resource activation is authorized merely by this document.

On suspected abuse: stop new dispatch, revoke affected invitation/credentials, request termination of provider handles, preserve minimized operation/audit evidence, determine exposure, rotate secrets, repair the failing control, and rerun relevant tests before reopening. Do not contact third parties or users without explicit authorization. Record material limitations openly; do not disguise them as successful audits.
